# 自动交易系统架构

## 设计目标

系统按低频到中频日内交易平台设计，目标是先建立可验证、可回放、可审计的交易闭环，再逐步接入真实券商。

第一阶段只做研究和模拟执行，不自动下实盘订单。

## 核心原则

策略只输出 `OrderIntent`，不能直接调用券商接口。所有订单必须经过：

```text
MarketData -> Strategy -> RiskManager -> OMS -> BrokerAdapter
```

这样同一套策略可以运行在：

- 历史回测
- 市场回放
- Shadow Mode
- 模拟券商
- 真实券商

## 首期策略

### 开盘区间突破

适合趋势、放量、指数和行业方向一致的交易日。策略等待开盘区间形成后，只在价格突破区间且位于 VWAP 有利侧时产生信号。

### VWAP 均值回归

适合震荡、价差稳定、无重大事件的环境。策略只在价格显著偏离 VWAP 且没有趋势过滤禁用时产生信号。

## 风控底线

- 单笔风险默认不超过账户净值的 0.15%。
- 同时开放风险默认不超过账户净值的 0.75%。
- 单日亏损达到阈值后停止新增仓位。
- 风控暂停状态会阻止所有新订单审批，直到人工或后续控制流程恢复。
- 日股数量必须按 100 股交易单位向下取整。
- 当前版本不允许隔夜持仓。

## OMS 状态机

当前 OMS 只负责本地订单状态登记，不连接真实券商。重复注册同一个 `client_order_id` 会返回已有订单记录，避免重复登记。

`UNKNOWN` 状态用于网络超时或券商响应丢失等不确定场景，后续必须通过对账解决。

## 本地执行账本

当前账本只在内存中记录订单、成交和持仓，用于研究、回放和模拟。它会计算持仓数量、平均价格和已实现 PnL，但不替代真实券商对账。

## 对账检查

当前对账检查比较本地 OMS、账本和券商快照，发现未知订单、本地缺失券商订单或持仓数量不一致时会报告严重差异，并可暂停风控审批。

## 模拟券商

当前模拟券商只用于测试、回放和模拟。它实现内部 broker adapter 接口，但不连接真实券商，也不独立根据行情撮合订单。

模拟券商可以导出券商状态快照，供对账检查复用。

## 回放执行

当前回放执行循环将策略、风控、OMS、模拟券商、保守成交模型和对账检查串联起来，只用于本地 fixture 验证。

## 后续接入边界

首个真实 API PoC 改为在 macOS 上通过 Moomoo OpenAPI/OpenD 进行美股只读账户与市场能力发现，后续再验证模拟交易。该 PoC 不允许实盘下单，也不改变日股研究主线。

Moomoo JP 当前不支持日股现货实盘 API 交易，因此 kabu Station 仍保留为后续日股执行通道；IBKR 作为美股备选通道。所有通道都必须复用同一个券商无关边界。

真实券商适配器必须实现：

- 下单
- 撤单
- 查询开放订单
- 查询持仓
- 查询成交
- 账户资金同步
- 重启后的账本核对

在这些能力没有通过测试前，不应接入真实资金。
